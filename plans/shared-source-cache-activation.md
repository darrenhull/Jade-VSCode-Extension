# Shared source-cache activation proposal

Status: read-only design for manager approval. No product activation, package or release is authorized by this document. The matched adapter and actual database-free process matrix are frozen at consumer commit160067e. Large-workspace performance remains a separate gate.

## Existing native contract

- One packaged CliWorkingSession owns transport. Doctor is database-free with config:{}; capabilities.sourceIndex must advertise format2, nativeVersion, databaseRequired:false and source.index.refresh/source.index.prepare/source.index.browser.update.
- Explicit refresh packet: request('source.index.refresh',{config:{workspaceRoots:[selectedRoot]}}). Reply has compact cache binding/counts, not source entries. Each selected project/root is refreshed separately; unrelated Git repositories are not combined.
- Ordinary build/test/Workspace already call WorkingEngine.prepareProject internally. That routine discovers current Git paths and reads the same v2 cache. The extension must not call source.index.prepare first merely to supply UI metadata.
- SourceIndexCache v2 shards remain the sole shared store; C++ remains the sole writer. Browsing metadata is advisory, and current raw bytes must validate it. Native InputInventory remains successful-load authority.

## Smallest proposed wiring

1. extension.js creates CliWorkingSession before registerLanguageTools and injects that existing client. No second service/client/cache is introduced.
2. SourceIndexCache accepts a lazy nativeVersion resolver in addition to the existing fixed value. A supplied resolver selects shared mode synchronously; loadShared awaits and validates it before reading rows. Unsupported or failed capability discovery stays an explicit shared-mode error, never a transient v1 writer. Resolve doctor metadata once per bundled-client lifetime, not once per source file. Existing legacy-mode unit controls can remain isolated until migration is complete.
3. language-tools.js supplies the lazy database-free doctor resolver and existing request callback. A small cache savedUris() reader exposes only validated owning-root advisory/native-path candidates already read from the same shards. The SourceIndex list callback uses these paths, replacing its VS Code findFiles pass. No native prepare/hash/discovery is launched for browsing. SourceIndex reads original saved bytes, hashes once and skips decode/parse when its accepted parser/version-bound metadata has the same digest. The optional current-proof callback remains unwired; cached native.hash is not a fresh source proof.
4. registerLanguageTools returns refreshSourceIndex(folder): execute one explicit native refresh for that root, verify the compact binding, reload saved cache rows while retaining open editor models, and resume ordinary browser work. Missing/old/corrupt data gives the existing Initialise/Refresh actions and the original native cause; no silent recursive fallback or default full rebuild. Root/folder changes invalidate old saved bindings while preserving editor buffers.
5. workspace-initialization.js invokes refreshSourceIndex after successful native configuration initialization and reports the two steps honestly. Existing configuration/profile repair and file-preservation safeguards remain. Initializing/locating Git stays native/setup-owned; a missing Git installation/worktree produces its real actionable error, not a JavaScript Git implementation. Explicit Object Explorer/Class View refresh calls this same method once before its existing rescan. Source-pull completion with rescan:false must not trigger another global refresh.
6. compile-inputs.js separates existing save/ownership checks from optional frontend discovery. Ordinary build/test use save-only mode, preserve selected and owned dirty native-source saves, abort on save failure and omit the redundant discovered config.files list. The native operation then performs the one complete preparation. Compile Problems clearing uses the selected resource and already-known owned diagnostic URIs, not another disk scan. Selected test methods/classes retain the already-tested fast path independent of global browser readiness. Stage logging says saving before native preparation, without claiming a frontend discovery phase.
7. Scratch Pad retains its current exact sourceText snapshot/selection/version immediately when run is requested. Its configuration currently performs no findFiles/save-all step, so no preparation request is added. Dependencies continue to be saved disk sources; dirty unrelated CLS buffers are not saved by Scratch Pad. Schema picker discovery is a browsing action and must not be inserted into a run whose schema is already selected.

## Debug inventory gate

Debug currently calls workingFiles and then config.files.flatMap(readFile) for source maps. An advisory browsing list is insufficient. No existing successful-native-input descriptor API is present. Do not remove debug discovery or substitute an empty/browsing-only list without a reviewed replacement.

Smallest native extension proposed for manager approval: successful compile report includes a compact descriptor of the EXISTING Working native-inputs-v1.json: exact owned path, raw SHA256 and current nativeInputsProof/Working identity. No second index, full source graph frame or extra source prepare is required. The consumer verifies descriptor containment/identity/hash, filters entries to owning roots and existing class source, reads original bytes and requires each hash to match the successful native inventory before making source maps. A changed ledger/file fails or retries explicitly. The ledger can contain prior inputs outside the current selected scope and deleted paths, so those must not be treated as current mapping inputs blindly. Source text encoding must use the existing raw-byte decoder. Native owner confirmed this descriptor is not already available; no implementation is requested until the manager approves it. Without that contract, debug activation is a stated remaining gate.

## Required focused regressions before enabling defaults

- Hold doctor capability discovery while queuing saved updates: no v1 directory/write, no fallback client, no unhandled rejection; unsupported capabilities keep dirty editor features usable and report the real repair/update action.
- Existing valid v2 startup reads candidate paths from shards and performs no VS Code findFiles or native prepare; unchanged saved raw bytes do not reparse. Missing/v1/incompatible cache performs no hidden full scan.
- Explicit refresh/Initialize invokes exactly one native refresh for the chosen root; preserves dirty/open buffers, configuration bytes and other project roots; failed refresh does not claim indexing complete. Two unrelated Git roots are handled separately.
- Ordinary build/test preserve save false/throw/snapshot/owned-root behavior and call native with no redundant frontend file inventory. Held SourceIndex.ready/discovery never prevents a selected method/class run from reaching native transport.
- Scratch runs execute each requested unsaved snapshot, preserve saved dependency bytes and never save unrelated dirty documents or request a separate prepare.
- Debug descriptor is a separate required contract test: stale/missing/outside inventory or changed source refuses guessed maps; a native-confirmed generated source position remains exact. Publish review continues using its existing frozen snapshot, dirty-source and target guards.
- Then rerun the actual process matrix, complete large-workspace cold/warm/change qualification, full default/affected PowerShell checks, coherent distribution/portable/VSIX identity and actual changed running-UI evidence. Do not claim release or installation from these focused stages.
